# Project Instructions

## Project Overview

CNV Scenarios is a performance and scale QE test suite for OpenShift Virtualization (CNV) workloads. It uses [kube-burner](https://kube-burner.github.io/kube-burner/) to orchestrate VM creation, lifecycle operations, and validation on OpenShift clusters. The codebase is entirely shell scripts and YAML — no compiled languages. Tests produce structured JSON validation reports and support both quick sanity runs and full regression modes.

## Tech Stack

- **Shell (Bash)** — Primary scripting language for test runners and validation scripts
- **YAML** — kube-burner configuration files, Kubernetes manifests, and vars files
- **kube-burner** — Test execution engine for Kubernetes workload scenarios
- **oc / kubectl** — OpenShift and Kubernetes CLI for cluster interaction
- **jq** — JSON processing for validation and structured reporting
- **Makefile** — Build automation and test group execution

## Running Tests

```bash
# Single test (sanity = minimal resources, full = production configs)
./run-workloads.sh cpu-limits --mode sanity
./run-workloads.sh cpu-limits --mode full

# Guest OS selection: linux (default), windows, or both
./run-workloads.sh cpu-limits --mode sanity --os linux
windowsImageUrl='http://host:9002/win.qcow2' ./run-workloads.sh cpu-limits --mode sanity --os windows
windowsImageUrl='http://host:9002/win.qcow2' ./run-workloads.sh --all --mode sanity --os both

# Override variables via environment (case-sensitive camelCase!)
cpuCores=8 ./run-workloads.sh cpu-limits --log-level=debug

# Multiple tests
./run-workloads.sh cpu-limits memory-limits disk-limits --mode sanity

# All tests in parallel
./run-workloads.sh --all --mode sanity --parallel

# List available tests (shows OS support per test)
./run-workloads.sh --list

# Direct kube-burner (from test directory)
cd resource-limits/cpu-limits
runTimestamp="run-$(date +%Y%m%d-%H%M%S)" kube-burner init --config=cpu-limits-test.yml --user-data=vars.yml
```

Results go to `/tmp/kube-burner-results/<test-name>/run-<os>-YYYYMMDD-HHMMSS/`.

## Development Conventions

- **Test runner**: `run-workloads.sh` is the unified entry point for all tests
- **Modes**: `--mode sanity` (quick validation with `vars-sanity.yml`) and `--mode full` (regression with `vars.yml`)
- **Variable override**: Environment variables override `vars.yml` values (case-sensitive)
- **Variable naming**: camelCase and case-sensitive (e.g., `cpuCores`, `vmsPerNamespace`, `storageClassName`)
- **Results**: Stored in `/tmp/kube-burner-results/<test>/run-<os>-YYYYMMDD-HHMMSS/`
- **Validation**: All tests produce structured JSON reports (`validation-*.json`) with pass/fail status
- **Shell standards**: All `.sh` files must pass `shellcheck` and `shfmt -d -i 4 -ci`
- **SSH validation**: Percentage-based sampling with configurable retry logic; Windows guests use `virtctl ssh` + PowerShell (see `docs/windows-image-build.md`, `guestOS` / `windowsImageUrl` in vars)
- **Sanity configs**: Use `TIMESTAMP` placeholder in `testNamespace` for runtime uniqueness
- **SSH auth**: Key-based auth for most tests; minimal-resources uses password-based auth via `sshpass`
- **Windows testing**: Only `windowsImageUrl` is required as a CLI override to run Windows tests with `--os windows`. The runner auto-corrects `vmUser`, `maxWaitTimeout`, `windowsRootDiskSize`, `max_ssh_retries`, and `vmMemory` (see auto-corrections table below).
- **File extension**: `.yml` (not `.yaml`) for all vars and template files

## Architecture

### Test Runner (`run-workloads.sh`)

Central orchestrator. Key internals:

- **TEST_REGISTRY**: Associative array mapping test names to `"relative_dir:config_file:vars_extension"`. Add new tests here.
- **TEST_ORDER**: Array controlling `--all` execution order.
- **TEST_OS_SUPPORT**: Associative array mapping test names to `linux`, `windows`, or `both`. Controls which OS variants are generated by `--os`.
- **Mode handling**: `--mode sanity` uses `vars-sanity.yml`, `--mode full` uses `vars.yml`.
- **OS handling**: `--os linux` (default), `--os windows`, or `--os both`. Each test is expanded into qualified names (`test:linux`, `test:windows`). Linux-only tests (minimal-resources, virt-capacity-benchmark) are skipped with `--os windows`; Windows-only tests (hammerdb-mssql) are skipped with `--os linux`.
- **Vars processing**: Before passing to kube-burner, `sed` replaces `TIMESTAMP` placeholders with unique suffixes, updates `resultsPath` and `runTimestamp`.
- **Windows auto-corrections**: When `guestOS=windows`, the runner automatically sets safe defaults unless explicitly overridden via environment:

  | Variable | Auto-set value | Why |
  |---|---|---|
  | `vmUser` | `Administrator` | Linux defaults (`fedora`, `cloud-user`) fail SSH to Windows |
  | `maxWaitTimeout` | `30m` | CDI image import + Windows boot is slow |
  | `windowsRootDiskSize` | `90Gi` | Windows images are much larger than Linux cloud images |
  | `max_ssh_retries` | `20` | Windows SSH service starts later than Linux |
  | `vmMemory` / `memory` | `2Gi` (if below) | Windows Server minimum is 2Gi; tests like per-host-density default to 256Mi for Linux |

- **Setup dispatcher** (`run_setup()`): Per-test pre-execution hooks (e.g., auto-detect `targetNode` for per-host-density, auto-detect `baseInterface` for nic-hotplug).
- **Cleanup dispatcher** (`run_cleanup()`): Per-test post-execution cleanup. Generic tests delete their `testNamespace`; per-host-density deletes by label.
- **Parallel mode**: Each test runs in a subshell; results are recovered from `summary.json` files since bash associative arrays don't propagate from subshells.

### Validation System (Two-Tier)

**Global scripts** (`config/scripts/`):
- `check.sh` (large shared library): All standard validation functions + helpers (retry, SSH, JSON reports). Used by most scenarios including Windows branches where applicable.
- `wrapper.sh`: Dispatcher that resolves `check.sh` path, creates results dir, pipes output to tee, preserves exit code.

**Local scripts** (`scale-testing/*/config/scripts/check.sh`):
- Used by per-host-density and virt-capacity-benchmark.
- Separate copies because they need **percentage-based sampling** (validate N% of VMs via SSH) rather than validating all VMs.

**How validation is triggered**: kube-burner's `beforeCleanup` hook in scenario config files calls `wrapper.sh` with the validation function name and parameters as Go template expansions:
```yaml
beforeCleanup: "../../config/scripts/wrapper.sh check_cpu_limits {{ $jobCounterLabelKey }} ..."
```

### Scenario Structure

Each test follows this pattern:
```
<category>/<scenario-name>/
├── <scenario>-test.yml                  # kube-burner config (Go templates)
├── vars.yml                             # Full mode variables
├── vars-sanity.yml                      # Sanity mode variables (minimal resources)
├── vm-<scenario>-template.yml           # Linux VM spec template
├── vm-<scenario>-windows-template.yml   # Windows VM spec template (if OS=both)
└── templates/
    └── secret_ssh_public.yml            # SSH key secret
```

**Kube-burner config files** use Go template syntax (`{{ .varName }}`). Variables come from the vars file passed via `--user-data`. The `counter` variable is special: setting `counter=0` triggers a cleanup-only job.

### Shared Resources

- `config/metrics-profiles/kubevirt-metrics.yaml`: Standard KubeVirt Prometheus metrics profile.
- `config/templates/dummy-configmap.yml`: Trigger object for `beforeCleanup` execution.
- `config/scripts/detect-available-interface.sh`: Auto-detects unused physical NIC on worker nodes.
- `config/scripts/cleanup-nncp.sh`: Cleans up NodeNetworkConfigurationPolicies after nic-hotplug.

### Windows VMs

8 scenarios support `--os windows` (or `--os both`), plus 1 Windows-only scenario. All Windows VMs use **CDI DataVolume** imports for the root disk (`windowsImageUrl`: `docker://…` for registry, or `http(s)://…/.qcow2` for HTTP import). SSH validation uses **`Administrator`** (auto-detected by the runner) and **PowerShell** over `virtctl ssh`. KubeVirt **`accessCredentials`** use **`qemuGuestAgent`** propagation with an explicit **`users`** list aligned to **`vmUser`** (the guest image must include the QEMU guest agent and OpenSSH).

**Per-flow Windows validation details:**

| Scenario | Validation Phases | Windows-specific behaviour |
|---|---|---|
| **cpu-limits** | 4 phases: VM discovery, spec vCPU count, guest OS CPU count (WMI), CPU burn workers | Phase 4 **bootstraps** `CNV_CPU_BURN=1` workers via SSH + `Invoke-CimMethod Win32_Process.Create` (base64-encoded PowerShell, bypasses SSH quoting). Workers are detached from the SSH session via WMI. Idempotent -- skips if workers already running. |
| **memory-limits** | 4 phases: VM discovery, spec memory, guest OS memory (WMI), memory burn workers | Phase 4 **bootstraps** 4 `CNV_MEM_BURN=1` PowerShell workers that each allocate 90%/4 of VM memory as byte arrays, fill with random data, and touch every page. Workers launched via `Invoke-CimMethod` (same pattern as cpu-limits). Validates exact worker count and free memory pressure drop. Guest memory checked via `Win32_ComputerSystem.TotalPhysicalMemory` with 15% tolerance. |
| **disk-limits** | 5 phases: VM discovery, spec disk count, spec disk sizes, guest OS disk count (WMI), guest OS disk sizes | Uses `Get-Disk` for non-system disk enumeration. Root disk uses separate `windowsRootDiskSize` variable (default 90Gi) to accommodate the large Windows image. |
| **disk-hotplug** | Dedicated `check_disk_hotplug_windows_guest()` | Initializes offline/RAW disks via `Get-Disk` + `Initialize-Disk` (GPT + NTFS). Reports data disk count and total size via WMI. |
| **nic-hotplug** | 5 phases: NNCP, NAD, VM config, running, guest OS | Windows guest validation checks VirtIO network driver presence (`Get-NetAdapter` InterfaceDescription `*VirtIO*`), active interface count (`Get-NetAdapter` Status Up), and test IP assignment (`Get-NetIPAddress` 192.168.*). |
| **high-memory** | 3 phases: VM discovery, VM responsiveness, guest OS memory | Guest memory checked via `Win32_ComputerSystem.TotalPhysicalMemory` with 15% tolerance. SSH responsiveness via `echo SSH_OK`. |
| **large-disk** | 4 phases: VM discovery, VM responsiveness, disk visibility, disk size | Uses `Get-Disk` non-system for visibility, `.Size` bytes-to-GB conversion for size validation with 5% tolerance. |
| **per-host-density** | 3 phases: VM discovery, running state, SSH sample | SSH validation uses `powershell.exe -NoProfile -Command "$env:COMPUTERNAME; echo SSH_OK"`. Sample N% of VMs (default 100% sanity, 25% full). Any SSH failure = test FAIL. |
| **hammerdb-mssql** | 12-phase `check_windows_vm` | MSSQL service check, disk init, disk count/size, HammerDB process polling, post-benchmark disk utilization, FIO data generation on extra disks, aggregate total disk utilization. |

- **hammerdb-mssql** ([database/hammerdb-mssql/](database/hammerdb-mssql/)) -- Windows-only scenario: MSSQL + HammerDB results file polling via `check_hammerdb_mssql` / `check_windows_vm` in `config/scripts/check.sh`.

Image build, registry push, and operational notes: [docs/windows-image-build.md](docs/windows-image-build.md). Reference manifests: [config/templates/vm-windows-base.yml](config/templates/vm-windows-base.yml), [config/templates/sysprep-configmap.yml](config/templates/sysprep-configmap.yml).

### Validation Phase Reference

Detailed comparison of what each validation phase checks on Linux vs Windows. Phase names match the `phase` field in structured JSON reports (`validation-*.json`).

#### cpu-limits (`check_cpu_limits`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `vm_discovery` | VMs exist with label | `oc get vm -l ...` | Same | Exact (>0) | Never |
| `vm_spec_cpu_count` | cores x sockets in spec | `oc get vm` jsonpath | Same | Exact | Prior FAIL |
| `guest_os_cpu_count` | Logical CPUs in guest | `nproc` | WMI `NumberOfLogicalProcessors` | Exact | No SSH creds |
| `stress_ng_processes` | CPU workload running | `ps aux \| grep stress-ng-cpu` (count = expected vCPUs) | Bootstrap `CNV_CPU_BURN=1` workers via `Invoke-CimMethod`, count via WMI | Exact (= vCPU count) | No SSH creds |

#### memory-limits (`check_memory_limits`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `vm_discovery` | VMs exist | `oc get vm` | Same | Exact | Never |
| `vm_spec_memory` | Spec memory request | `oc get vm` jsonpath | Same | Exact string | Prior FAIL |
| `guest_os_memory` | Guest total RAM | `free -m` | WMI `TotalPhysicalMemory/1MB` | +/-15% | No SSH |
| `stress_ng_processes` | Memory workload running | `ps aux \| grep stress-ng` (>0 = PASS, 0 = FAIL) | Bootstrap 4x `CNV_MEM_BURN=1` workers (90% RAM / 4, min 32MB each), count via WMI, free memory pressure check | Linux: >0; Windows: exact 4 | No SSH |

#### disk-limits (`check_disk_limits`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `vm_discovery` | VMs exist | `oc get vm` | Same | Exact | Never |
| `vm_spec_disk_count` | Data volumes in spec | jq volumes (excl root/cloudinit) | Same | Exact | Prior FAIL |
| `vm_spec_disk_size` | DV storage requests | jq dataVolumeTemplates | Same | Exact | Prior FAIL |
| `guest_os_disk_count` | Data disks in guest | `lsblk --json` (excl vda/sda/zram) | `Get-Disk` non-system | Exact | No SSH |
| `guest_os_disk_size` | Per-disk size | `lsblk` sizes | `Get-Disk Size/1GB` | 5% or >1GB | No SSH |

#### disk-hotplug (`check_disk_hotplug`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `vm_spec_disk_count` | Hot-plug volumes | jq volumes | Same | Exact | Never |
| `vm_spec_pvc_size` | PVC storage size | `oc get pvc` | Same | Exact | `validate_pvc_by_size=false` |
| `guest_os_disk_count` | Visible hot-plug disks | `lsblk --json` | `Get-Disk` + `Initialize-Disk` (GPT/NTFS) | Exact | `validate_hotplug_from_os=false` |
| `guest_os_disk_size` | Per-disk size | `lsblk` sizes | `Get-Disk Size/1GB` | 5% or >1GB | Same as above |

#### nic-hotplug (`check_nic_hotplug`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `nncp_validation` | NNCP count + Ready | `oc get nncp` + Available=True | Same | Exact (NIC count x 2) | Never |
| `nad_validation` | NAD count | `oc get nad` by label | Same | Exact | Never |
| `vm_config` | Networks + interfaces in spec | `oc get vm` jq | Same | Exact (NIC count + 1) | Never |
| `vm_running` | All VMs Running | `printableStatus` | Same | Exact | Never |
| `guest_os` | Interface count in guest | `ip -br link show` | VirtIO driver check + `Get-NetAdapter` Up count | Exact (NIC count + 1) | No SSH / `validate_guest_os=false` |

#### high-memory (`check_high_memory`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `vm_discovery` | VMs exist | `oc get vm` | Same | Exact | Never |
| `vm_responsiveness` | SSH reachable | `uptime` | `echo SSH_OK` | -- | Prior FAIL |
| `guest_os_memory` | Guest total RAM | `free -m` | WMI `TotalPhysicalMemory/1MB` | +/-15% | Prior FAIL |

#### large-disk (`check_large_disk`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `vm_discovery` | VMs exist | `oc get vm` | Same | Exact | Never |
| `vm_responsiveness` | SSH reachable | `uptime` | `echo SSH_OK` | -- | Prior FAIL |
| `disk_visibility` | Non-root disk present | `lsblk --json` | `Get-Disk` non-system | Presence | Prior FAIL |
| `disk_size` | Disk size in GB | `lsblk -b` or `/sys/block/*/size` | `Get-Disk .Size` bytes to GB | +/-5% (min 1GB) | Prior FAIL |

#### per-host-density (local `check.sh`)

| Phase | Check | Linux | Windows | Tolerance | Skip |
|---|---|---|---|---|---|
| `vm_discovery` | VMs exist by label | `oc get vm` | Same | Exact | Never |
| `vm_running_state` | All VMs ready | `status.ready==true` | Same | Exact | Never |
| `ssh_validation` | SSH sample N% | `hostname && echo SSH_OK` | `$env:COMPUTERNAME; echo SSH_OK` via PowerShell | Any failure = FAIL | No SSH creds / percentage=0 |
| `vm_shutdown_state` | All VMs Halted | `runStrategy==Halted` | Same | Exact | Never |

#### hammerdb-mssql (`check_windows_vm`, Windows-only)

| Phase | Check | Method | Tolerance | Skip |
|---|---|---|---|---|
| `vm_discovery` | VMs exist | `oc get vm` | Exact | Never |
| `ssh_check` | SSH connectivity | `echo SSH_OK` | -- | `validateSSH=false` |
| `os_check` | OS caption match | WMI `Caption` vs pattern | Substring | `validateOS=false` |
| `app_check_{svc}` | Service running | `Get-Service` | Exact "Running" | No `validateApps` |
| `cpu_check` | CPU count | WMI `NumberOfLogicalProcessors` | Exact | `validateCPU=false` |
| `memory_check` | Total RAM | WMI `TotalPhysicalMemory/1MB` | +/-5% | `validateMemory=false` |
| `nic_check` | NIC count with IPv4 | `Get-NetAdapter` + `Get-NetIPAddress` | Exact | `validateNICs=false` |
| `disk_init` | Initialize offline disks | `Get-Disk` + `Initialize-Disk` | -- | `initializeDisks=false` |
| `disk_check` | Disk count + total size | `Get-Disk` non-system | Count exact, size +/-5% | `validateDisks=false` |
| `disk_util` | Used space on data volumes | `Get-Volume` non-C: | +/-10% (min 5GB) | `validateDiskUtil=false` |
| `disk_util_after_process` | Post-process used space | Poll `Get-Process`, then `Get-Volume` | +/-10% (min 5GB) | `validateDiskUtilAfterProcess=false` |
| `fio_datagen` | FIO data gen on extra disks | Deploy FIO, run `fio-datagen.ps1`, validate per-drive dir/file/size | Exact counts | `fillExtraDisks=false` |
| `total_disk_util` | Aggregate total non-C: util | `Get-Volume` non-C: (HammerDB + FIO) | +/-`diskUtilTolerancePct`% | `fillExtraDisks=false` or `expectedTotalDiskUtilGB=0` |

## Adding a New Scenario

1. Create directory under the appropriate category with config, vars, vars-sanity, and template files.
2. Add entry to `TEST_REGISTRY` in `run-workloads.sh`: `["my-scenario"]="category/my-scenario:my-scenario-test.yml:yml"`
3. Add to `TEST_ORDER` array.
4. Add validation function to `config/scripts/check.sh` (or create local check.sh for scale scenarios).
5. Wire validation via `beforeCleanup` in the kube-burner config calling `wrapper.sh`.
6. If pre-execution setup is needed (auto-detection, etc.), add a `setup_*` function and register it in `run_setup()`.
